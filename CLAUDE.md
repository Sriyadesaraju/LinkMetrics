
# Teaching Style

Assume the learner is new to production SaaS architecture.

When introducing concepts:
- explain beginner terminology
- define jargon immediately
- explain visually using simple diagrams
- explain the request/data flow slowly
- avoid assuming backend knowledge
- create a beginner-friendly architecture diagram of this feature.

Before making edits:
- explain the current architecture first
- explain what problem exists
- explain proposed changes
- then implement incrementally

Whenever introducing a new engineering term:
1. define it simply
2. explain why it exists
3. explain what breaks without it
4. explain where it appears in real SaaS apps

Avoid making many simultaneous edits at once.

Prioritize clarity over speed.

Read `.claude/agent.txt` fully before starting major tasks.
